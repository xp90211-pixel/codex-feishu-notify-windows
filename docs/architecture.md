# 架构与边界

## 生命周期、入队与投递

Windows 入口使用离线编译的 GUI 子系统 `notification-host.exe`，固定允许 `notify`、`dispatch`、`drain` 三种模式，不接受任意脚本或命令。它以 `UseShellExecute=false`、`CreateNoWindow=true` 创建 PowerShell，严格处理 Windows argv 引号并并发读取 stdout/stderr。计划任务调用 `host drain`，notify 命令链调用 `host notify/dispatch`；生命周期 Hook 则复用 Codex 已有的 PowerShell shell。第三方包装器自身的启动行为保持原样。源文件与 EXE 均纳入安装事务备份。

### 1. Codex 生命周期 Hook

安装器把本项目处理器合并进用户级 `~/.codex/hooks.json`，不覆盖其他处理器：

- `PermissionRequest`：创建 `needs-input` 队列项并显示可撤销的 Windows Toast；不返回批准或拒绝决定；
- `PostToolUse`：按请求 ID 匹配；无请求 ID 时按 turn、工具及规范化输入哈希唯一匹配，不相关事件或多义匹配不清理。`UserPromptSubmit` 清理会话等待项；
- `SessionStart`：写入会话就绪标记，表明该会话已经实际加载生命周期 Hook；
- `Stop`：只给当前主任务写入短期完成标记，并返回 `{"continue":true}`；不阻止或自动继续任务；
- 不注册 `SubagentStop`，因此子代理不能给根任务完成门登记。

Hook 同步执行短时本地状态操作并共享状态锁，不设置审批决定；同一会话的不同授权请求分别存储，有 ID 的已结束请求留短期墓碑以拒绝迟到重放。无 ID 时用带随机 epoch 的本地递增代数，不能证明任意外部乱序事件的完整因果关系。权限等待是否真正发生由 Codex 官方事件决定，脚本不扫描终端文本，也不猜测 UI 状态。

### 2. Codex 完成通知

`notify.ps1` 接收 Codex JSON 载荷，只进行以下本地操作：

1. 验证事件类型；
2. 跳过飞书来源回合和已知内部提示；
3. 可选地确认线程出现在 Codex 桌面状态中；
4. 对已经存在 `SessionStart` 就绪标记的新会话，严格模式原子消费由同一 `session-id/turn-id` 的 `Stop` Hook 写入的完成标记；没有标记则不发送；安装 Hook 前已经打开的旧会话没有就绪标记，暂时沿用兼容发送，重新开启 Codex 后自动进入严格模式；
5. 截断并脱敏任务/结果预览；
6. 以 `thread-id|turn-id` 的 SHA-256 前 40 位作为事件 ID；
7. 当 `transport.enabled=true` 时原子写入 `spool/pending`；关闭时跳过飞书队列；
8. 根据 PC 通知设置尽力显示 Windows Toast，不受飞书总开关影响。

它不联网、不直接发飞书，也不启动计划任务。PC 前台判断只影响本机 Toast；飞书开启时，队列按计划任务规则处理。

### 3. 计划投递

`drain.ps1` 通常由日常、每周全天补齐和日期明确的节假日 Windows 计划任务触发器调用；用户在非运行时段点击“马上开始”时，还会暂时增加一条有明确到期时间的命名触发器。

固定日常触发器是真正的 `MSFT_TaskDailyTrigger`：

- `DaysInterval=1`；
- 默认起点 18:40；
- `Interval=PT1M`；
- `Duration=PT7H20M`；
- `StopAtDurationEnd=true`；
- `StartWhenAvailable=false`；
- `AllowDemandStart=false`。

启用节假日日历后，安装器还为每个未来节假日创建日期明确的 `MSFT_TaskTimeTrigger`。默认跨午夜时间窗 18:40–02:00 已覆盖节假日的 00:00–02:00 和 18:40–24:00，因此日期触发器只补齐 02:00–18:40，重复配置为 `PT1M / PT16H40M`。两类触发器共同构成节假日 00:00–24:00 的运行范围，同时不改变普通日限制。

选择固定“全天运行日”后，安装器用一个或两个 `MSFT_TaskWeeklyTrigger` 补齐时间窗外的缺口，并把所有选中的星期合并到相同触发器中。若日历中的节假日落在已选星期，安装器不再为该日期创建重复触发器。未选择任何星期时不创建每周触发器，保持原有行为。

每次排空在发送前都会重新计算当前有效状态。`spool/state/manual-delivery.json` 可保存两种有期限的覆盖：`force` 在正常时间窗外继续投递到下个计划触发边界，`pause` 则让已有触发器安全退出到下个计划触发边界。覆盖过期后读取时忽略，不产生读侧写入，长期时间窗不变。“马上开始”建立两秒后执行的临时命名触发器；不存在额外的直接排空进程，也不调用 `Start-ScheduledTask`。永久开关写入 `delivery.enabled` 与 `runtime-control.json`，优先于临时 force。

它使用本地 `lark-cli` 专用配置发送文本或交互式卡片，分开读取 stdout/stderr，超时终止；只有退出码 0、JSON code 0 与 message ID 同时存在才确认成功，并使用同一个幂等键做有限重试。成功后写入 `spool/sent/<event>.sent`，再删除待发文件。失败的项目保留，供窗口内下一次重试。

节假日触发器来自安装时复制到运行目录的 `holidays.local.json`，不会联网动态抓取。普通周末不是隐式节假日；只有日历明确列出的日期才扩展。官方发布新年度安排后，需要审核、更新日历并重新运行安装器。

## 图形控制层

`Settings-Gui.ps1` 是 WinForms 控制层，不复制计划任务注册逻辑。它负责发现现有任务和安装目录、读取受管配置或导入旧版脚本参数、校验表单，并把用户确认后的值转换为 `Install.ps1` 参数。安装完成后，它在独立 PowerShell 进程中运行 `Test-Configuration.ps1`，防止测试脚本的退出码关闭图形界面。

图形层遵守以下边界：

- 打开窗口和“检查配置”均为只读；
- 飞书会话 ID 默认遮挡，不写入界面日志；
- “保存设置”调用安装器的 SettingsOnly 路径，只保存配置、必要时重建时间触发器，不改写脚本、Codex 配置或 Hook；“安装通知”承担首次部署、升级和修复；
- 只有安装入口合并用户级生命周期 Hook、修复 `notify` 命令链；Hook 信任仍由用户在 Codex 中审查确认；
- “运行计划”使用独立分页，并显示节假日模式的运行说明以及周一至周日固定全天运行选项；
- 运行计划开关只启用或停用 `Codex.LarkNotify.codex`（或识别出的兼容任务），绝不按需运行；
- 动态“马上开始 / 立刻停止”按钮只建立有期限的临时投递覆盖；关闭运行计划、重新设置时间规则或卸载都会清除它；
- 飞书通知开关只改变 `transport.enabled`；关闭时 PC 通知继续，新事件不入队，现有待发项原子移入 `spool/suppressed`，重新打开不会自动补发；
- 窗口使用 DPI 自动缩放、可调整边框、分页设置区和可滚动页面；首次显示时会限制在当前显示器工作区内，窄窗口下操作按钮自动换行；
- “飞书连接”页底部的“安装通知 / 卸载通知”构成维护入口：安装使用当前表单值幂等部署或修复，卸载通过卸载器恢复安装前计划任务且只删除本项目拥有的 Hook；
- 不包含 `Start-ScheduledTask`；即时开始和后续排空均由临时时间触发器管理，不改变常驻 `LarkChannelBridge.Bot.codex`。

## 数据保留

| 数据 | 默认保留 | 说明 |
|---|---:|---|
| 待发队列 | 最长 24 小时 | 超时后转入 expired |
| 过期队列 | 7 天 | 便于短期排查，然后清理 |
| 已抑制队列 | 7 天 | 关闭飞书时转入，避免重新打开后意外补发；可人工审计或清理 |
| 已发送标记 | 90 天 | 含实际发送时间、事件 ID 和飞书 message ID，不含任务正文 |
| 完成门标记 | 10 分钟 | 只含 session/turn 标识和登记时间；消费后立即删除 |
| 等待状态 | 24 小时 | 用于撤销未发送等待项和对应 PC Toast |
| 会话就绪标记 | 30 天 | 区分安装前旧会话和已经加载 Hook 的新会话 |
| 手动投递覆盖 | 至下个计划触发边界 | 只含 `force/pause`、创建时间和到期时间；过期时只读忽略，重建任务时删除 |
| JSONL 日志 | 每份 2 MiB，当前 + 3 份历史 | 不记录原始 CLI stdout/stderr；仅状态和脱敏详情 |

## Hook 共存

Codex 用户配置只有一个顶层 `notify` 命令。安装器按顺序处理：

1. 无现有钩子：直接安装本项目钩子；
2. 现有包装器带 `--previous-notify`：把本项目放入其下游；
3. 任意可解析的现有钩子：通过 `dispatch.ps1` 串联；
4. 旧版 `lark-channel-notify/notify.ps1`：迁移为新钩子，避免重复；
5. 不能安全解析：停止并要求人工确认。

安装前后都会保留原始配置行和备份。卸载时只有在配置未被后续修改的情况下才自动恢复。

生命周期 Hook 使用独立的 `~/.codex/hooks.json`。安装器逐事件删除旧的本项目处理器、保留同组或其他组中的第三方处理器，再增加一个当前处理器；卸载时执行相反操作。无法解析 JSON 时安装器停止，不会覆盖。

## 已知限制

- 仅支持 Windows Task Scheduler。
- 当前只有 `lark-cli` 传输，不直接保存飞书应用密钥或 webhook。
- 内置新加坡日历覆盖 2026–2027，中国日历覆盖 2026；之后年份需要维护者更新或用户提供本地日历。
- Windows 单个任务最多容纳 48 个触发器；安装器最多生成 47 个持久触发器，预留 1 个给临时手动运行。
- `visible_threads_only` 读取 Codex 桌面本地状态，是尽力而为的过滤层；失效时可关闭。
- `notify` 的存在由 OpenAI 官方文档支持，但具体 JSON 字段可能随 Codex 版本变化，CI 无法代替真实客户端兼容测试。
- 新增或修改生命周期 Hook 后需要重新开启 Codex；静态配置检查不能证明真实 `PermissionRequest` 和 `Stop` 生命周期已经触发。
- 远程审批会改变授权边界，终端输入还依赖平台控制能力，因此均不在当前运行时中；评估见 `docs/remote-control-evaluation.md`。


## 安装与并发安全

完整 TOML 解析与词法闭合检查先于写入，保持未修改段落的 UTF-8 内容。所有任务触发器由同一纯计划生成器产生，诊断逐项比较时刻、重复间隔、持续时长与星期掩码，并忽略已过去的日期触发器。预检超出 47 个持久触发器时中止。

安装事务保存配置、Hook、运行文件和任务 XML；失败恢复到部署前快照。预检后的配置若已被其他操作修改，则拒绝陈旧写入。多个排空进程共享排空锁；每次实际 CLI 提交前共享状态锁，重新验证总开关、临时状态、目标配置及授权等待记录。关闭确认后不提交下一条请求；已提交的在途请求不能撤回。

发布使用 release-files.txt 的逐文件白名单；成品 ZIP 再验证路径、缺失/额外文件、隐私模式与已固定的 TOML 解析器哈希。一键 EXE 仅嵌入通过检查的 ZIP。
