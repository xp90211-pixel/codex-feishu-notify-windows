# 只提醒新状态与全部任务停止提醒

本功能属于 0.7.0 源码，尚未包含在已发布的 v0.6.1 安装包中。

## 开启与升级

从本版本源码安装或升级已有运行目录：

```powershell
.\scripts\Install.ps1 -InstallRoot '<已有通知运行目录>' -FreshNotificationsOnly -AllIdleReminder
```

不要把示例路径原样执行。安装器沿用原有收件人、时间窗、计划任务、内容隐私设置及无控制台宿主；仍由用户审查 Codex 提示的 Hook 信任变更。本操作不会发送测试消息。

- 新安装默认开启“只提醒新状态”；旧配置没有该字段时继续保持旧队列语义，须显式传入 `-FreshNotificationsOnly` 才迁移。
- 全部任务停止提醒默认关闭，须显式传入 `-AllIdleReminder`。旧的本地附加配置会保留，包括确认间隔。
- 已升级的运行时可用 `-SettingsOnly` 配合上述参数修改开关；加 `:$false` 可关闭。设置器保存其他选项、再次安装或升级均不会重置这些选择。目前两个选项通过安装参数或私有 JSON 管理，未增加 GUI 控件。

## 不补发历史

`settings.local.json` 的 `delivery.fresh_notifications_only=true`：

1. 飞书投递时段以外的新事件不入队，不会在晚间补发。PC Toast 仍独立遵守桌面设置。
2. 时段内的项目写入明确的起止边界；跨午夜视为同一时段，结束点不包含在内。节假日及固定全天日以当日 00:00–24:00 为边界。
3. 上一时段、没有边界标记的旧队列、未来时间戳，以及同一任务被新活动取代的未发完成项，不再投递。旧项移入 `spool/suppressed`，默认保留 7 天，不会自动回流。
4. 新提示、工具继续运行或请求授权会使该任务尚未发送的完成项失效；连续未发完成项只保留最新一项。真正启动 CLI 前再次持有状态锁核验，阻止已读入内存的旧项继续提交。
5. “马上开始”仅接收临时窗口建立后的新事件，不恢复之前积压。当前窗口内未确认的投递仍沿用原有有限重试和幂等键。

完成卡片改为“Codex 本轮回复完成”，时间标记为“事件时间”，不代表整个项目已完成。事件时间来自本机收到通知的时间；对客户端未提供因果标识的任意乱序事件无法保证完全重建顺序，严格完成门仍建议开启。

## 全部本机任务已停止

私有 `idle-reminder.settings.json`：

```json
{"schema": 1, "enabled": true, "channel": "feishu", "confirm_seconds": 5}
```

复用现有无闪窗投递进程，不创建额外的计划任务或常驻服务。

- 计划时段开始后的首次成功检查（宽限 120 秒）必须发现至少一项正在运行的本机 Codex 任务，才为该时段登记提醒。
- 当所有本机任务都已结束、停止或等待用户输入/授权，并经过至少 5 秒的二次确认后，发送一次蓝色飞书汇总：“Codex 当前没有运行中的任务”。普通单项通知继续保留。
- 一开始就空闲、启动太迟或起始状态无法确认时，不会假定曾经运行。新任务恢复运行会取消本次静默确认。持久化窗口标记避免重启重复；汇总过期后不跨时段补发。
- 手动临时投递不另开“全部停止”的监控时段。只统计本机 Codex 任务，不声称覆盖 ChatGPT、云端或远程主机。

状态来自桌面应用提供的本地 named pipe，只允许 `list_threads`、`read_thread` 两类只读调用。近期列表之外的已加载任务通过本机 writer-lock 标识补查，避免把列表截断当成全部停止。运行状态或清单不完整、超时、未知状态、应用关闭时均跳过汇总，不恢复、继续或审批任何任务。

这是对桌面应用内部接口的兼容适配，并非稳定的公共 API 保证；应用升级可能使其不可用。启用后下一次 Hook 会保存应用端点；未取得端点前不会发汇总。配置检查不调用真实应用状态接口，也不能证明实际飞书收件成功。

## 隐私和验证

汇总只含时间与等待介入的任务数，不包含任务标题、对话正文或授权内容。私有目录持久化本地管道名、任务标识和计数，不记录读取到的对话文本或凭据；不得提交端点状态、收件人、日志、队列或备份。

`Test-FreshNotifications.ps1` 和 `Test-AllIdleReminder.ps1` 使用隔离临时目录、离线 fake CLI 和模拟状态，覆盖跨午夜、旧队列隔离、最终提交检查、无重复、未知状态、等待输入、只读 DryRun 和卡片内容。测试不连接真实飞书，也不修改本机正在运行的通知安装。真实定时边界和真实收件需要另行现场验证。
